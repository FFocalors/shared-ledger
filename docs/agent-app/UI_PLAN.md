# Agent 应用端（只读阶段）UI 方案

范围：全局悬浮入口、助手面板（会话 / 事件 / 提案草稿展示与确认执行）。确认在 2026-10-22 起由 Agent 契约提供 202/501 两条响应；演示草稿永不可执行，后端草稿可以确认。
契约来源：`D:/project/Android/shared-ledger-agent/agent/contracts/v1.0.0/openapi.json`（api_version 1.0.0）。

## 题材与定位

一个多人活动记账 App 里的「记账助手」：用户用一句话说要记的账或想查的数，助手读账后回答，或拟一张记账草稿等用户确认。
面板最该被记住的是那张**记账草稿**——它是未签字的凭证，不是聊天气泡。其余元素都保持安静。

沿用 App 的 `SharedLedgerTypography`（系统 Sans）：助手回复用 `Body`，元信息用 `BodySecondary` / `Label`；草稿金额用现有金额样式（`SummaryStatValue` 或 `SubActivityAmount`，等宽数字 `fontFeatureSettings = "tnum"`）。不引入新字体。

## 悬浮入口：左下边缘的索引贴（2026-10-22 修订）

需求：平时半隐藏在屏幕左下边缘，点一下完整露出，再点一下打开助手面板。

概念：像夹在账本侧边的索引贴。收起时只露出一截贴在屏幕边上的贴条，展开时整枚按钮滑出、离开边缘，变成独立的圆形按钮。

```
收起（Tucked）                 展开（Revealed）
│                              │
│▐▌  ← 露出 24dp，靠边一侧直角，   │  ╭────╮
│▐▌    外侧半圆；中间一道竖向       │  │ ✎  │  ← 56dp 圆形，离左边缘 12dp
│      握条（3×16dp）             │  ╰────╯
│                              │
```

- 尺寸与位置：按钮本体 56×56dp，左下角，底部偏移 112dp + 导航栏 inset。收起时整体向左平移 32dp，只露 24dp；但点击热区补足到 48×56dp（向屏幕内延伸），满足最小触控尺寸。
- 形状：收起时靠屏幕边一侧圆角为 0、外侧 12dp（索引贴贴在边上）；展开时四角都是 28dp（圆形）。圆角随位移一起插值。这个形变就是唯一的动效重点。
- 内容：收起时只显示握条，告诉用户「这里可以拉出来」，不显示图标；展开时握条淡出、笔记图标淡入。
- 状态色：面板关闭期间如果有进行中或等你确认的回合，握条从 Cream 变成 Draft Amber（`#FED39C`），提示回去看。只换颜色，不闪烁、不脉冲。
- 交互：
  - 点收起的贴条 → 展开；点展开的按钮 → 打开面板。
  - 向右拖贴条也能展开，向左拖回收起。贴条区域用 `Modifier.systemGestureExclusion()`，避免和系统左滑返回手势冲突（排除区只覆盖贴条本身）。
  - 展开后 4 秒没有操作 → 自动收回；面板关闭后 → 立即收回；切换页面 → 收回。
  - 不拦截屏幕其他区域的点击。
- 动效：展开用 spring（`dampingRatio = 0.8`，`stiffness = StiffnessMediumLow`），收回用 200ms 标准缓动（`SharedLedgerMotion`）。展开时给一次轻触感（复用 `SharedLedgerHaptics` 的轻提示）。系统动画关闭时直接切换状态，不做插值。
- 无障碍：收起态的 contentDescription 是「展开记账助手」，展开态是「打开记账助手」。两种状态都提供一个自定义无障碍操作「打开记账助手」，读屏用户一步就能打开，不需要点两下。焦点环沿用 Draft Amber 3dp 描边。

### 自查

- 第一反应是「把原来的圆形 FAB 往左推一半」：换任何 App 都会这么做，而且左半圆贴在屏幕边上，看起来像被裁掉的按钮，不像是故意藏起来的。改为索引贴形状（贴边一侧直角）加握条，收起态有了自己的形态和含义。
- 原方案没有考虑左边缘是系统返回手势区，拖动会误触发返回。加了手势排除，范围只限贴条本身。
- 原方案收起态什么也不说明。加了状态色，让「有草稿等你确认」在面板关闭时也能看见，而且不引入任何非用户触发的动画。

## 助手面板 v2：阻尼抽屉与「落笔」动效（2026-10-22 修订）

需求：面板改为带阻尼橡皮筋回弹的底部抽屉，松手后按手势速度自动吸附锚点；面板观感偏素，适度加入当下流行的 AI 交互动效。

### 抽屉物理（`AgentBottomSheet`，替换 `ModalBottomSheet`）

```
屏幕顶 ───────────────────────────
  │  ↑ 橡皮筋区：上拉超过「全开」，位移按阻尼衰减，最多再走 64dp
  ├── 全开 Expanded：面板顶距屏幕顶 = 状态栏 + 8%·高（约 92% 高）
  │
  ├── 半开 Half：面板露出 55% 屏高
  │
  └── 关闭 Hidden：面板完全在屏幕下方 → 回调 onDismiss
```

- 锚点：Expanded / Half / Hidden 三个。打开时：已有对话 → Expanded；空对话 → Half。输入框获得焦点或软键盘弹出 → 自动到 Expanded。
- 跟手：拖动期间 1:1 跟手；越过 Expanded 继续上拉时，用橡皮筋公式 `d·(1 − 1/(x·0.55/d + 1))`（d = 64dp）衰减；同理在 Hidden 之下不需要处理（那就是关闭）。
- 松手吸附：用 `exponentialDecay` 按松手速度算出投射落点 `projected = offset + decay.calculateTargetValue(0, v)`，选离投射落点最近的锚点；另加速度门槛：|v| > 1800dp/s 时至少跨到相邻锚点（防止快甩只回原位）。
- 回位动画：`spring(dampingRatio = 0.82, stiffness = StiffnessMediumLow)`，把松手速度作为 `initialVelocity` 传进去，所以甩得快就冲得猛；从橡皮筋区松手用 `dampingRatio = 0.62`，有一次可见的回弹。
- 与列表联动（NestedScroll）：抽屉没到 Expanded 时，列表上滑先推抽屉；列表已滚到顶再下拉，拖的是抽屉；fling 同理把剩余速度交给抽屉吸附。
- 遮罩：Paper 之下铺 `Color.Black`，透明度随面板高度从 0 线性到 0.32；点遮罩 → 关闭。系统返回键 → 关闭（走同一条吸附动画）。
- 触感：吸附到 Expanded 或被甩关时给一次轻触感。
- 抓手：面板顶部居中 36×4dp 的握条（`AppOutlineVariant`），整个顶部 24dp 高区域都可拖。面板顶角 `SharedLedgerRadius.ExtraLarge`（24dp）。
- 系统「移除动画」开启时：吸附直接跳到目标锚点，没有橡皮筋回弹动画（拖动跟手仍保留）。
- 物理计算放在纯函数 `AgentSheetPhysics`（橡皮筋、投射落点、选锚点），单测覆盖。

### 「落笔」动效：AI 感来自账本，而不是霓虹

当下流行的 AI 动效是流式逐字出现、思考时的流光文字、内容生成时的描边。这里全部保留，但统一成「助手在纸上落笔」这一个隐喻，颜色只用现有的暖色，不引入紫蓝渐变、星光或极光边框。

1. **草稿落笔（唯一的高潮时刻）**：新草稿到达时，虚线描边沿卡片周长从左上角顺时针「画」出来（路径按长度 0→1 裁剪，520ms，`FastOutSlowIn`）；描边画完后票头条从左向右铺满（220ms）；最后金额数字从 0 滚到目标值（复用现有 `RollingCurrencyText` 的思路或组件，360ms）。同一草稿只播一次；从历史打开、或 revision 更新只做 120ms 交叉淡入。
2. **流式回复**：新到的助手消息按字逐步显现（每 16ms 约 2 个字，总时长封顶 700ms），尾部 6 个字带 0→1 渐显，像墨水晕开；正在显现时不显示光标、不加打字点。历史消息直接完整显示。
3. **思考流光**：回合进行中，状态行文字（「正在读取账目」等）上有一道光带从左向右扫过（`Brush.linearGradient` 平移，1.6s 一圈，颜色 SoftCharcoal → `#B07A3A` → SoftCharcoal，全程对比度 ≥ 4.5）。状态行左侧加一个 6dp 的琥珀色墨点，随流光节奏缓慢呼吸（缩放 0.8↔1.0）。回合结束即停。
4. **你说的话**：用户消息发出时从输入框位置向上「贴」到列表里（`animateItem` + 从 12dp 下方弹到位，spring），回应用户动作。
5. **发送 / 停止**：按钮图形在「发送箭头」与「停止方块」之间交叉缩放切换（150ms）。

### 空状态：给出可以直接点的说法

空对话时，提示文案下方给 3 个建议说法，点一下填进输入框（不自动发送）：
- 「昨天烧烤 750，我付的，四个人平分」
- 「这个活动现在谁还欠我钱？」
- 「我这次一共花了多少？」
样式：`SharedLedgerRadius.Input` 圆角、1dp `AppOutlineVariant` 描边、Paper 底，左对齐竖排，不加图标。

### 降级

系统「移除动画」开启时：草稿直接完整出现、回复直接完整显示、流光与呼吸停止（状态行静态显示）、按钮直接切换。

### 自查

- 第一版直觉是「紫蓝渐变光晕描边 + 星光图标 + 打字点」，这正是任何 AI 助手都会有的样子，而且和 App 的鼠尾草绿/暖橙完全不搭。推翻，改为把所有动效收束成「落笔」一个隐喻：描边被画出来、字像墨水晕开、状态行有暖色流光。
- 原计划同时让每条消息、每张卡片都有入场动画，属于「每段都淡入」的套路。收紧为：只有草稿落笔是编排好的高潮；流式回复与流光是真实过程的反馈（模型在工作），用户消息上贴是回应用户操作。
- 抽屉初版只有两档（开/关），甩动手感单薄。加了半开锚点、按速度投射选锚点、把松手速度喂给弹簧，以及橡皮筋区单独更软的回弹，让「甩」和「拉过头」都有可感知的物理反馈。

## 助手输出 v3：账页与统一输出语法（2026-10-25 修订）

背景：真机连上真实服务后，回复是服务端模板拼出来的纯文本（`债务记录：zhy → whr，1.3833 CNY`），整屏只有文字；同时流式显示在结尾处停在半透明（`streamedText` 先把进度限制到文本长度，「已完成」的判断永远不成立，最后 6 个字一直渐隐，已修）。

### 输出分类与统一语法

所有助手输出共用一套语法：**正文无容器；记录进「账页」；状态与结果是一行带图标的状态条**。类型靠图形（图标形状）区分，不靠颜色区分。

| 类型 | 来源 | 呈现 |
|---|---|---|
| 回答正文 | 无法识别为记录的句子 | 无容器的正文，逐字流入 |
| 账页 | 消息里的债务、消费、活动、欠款方向、退款、预存行 | 一张白色纸页：1dp 细描边、12dp 圆角，页眉一行 + 发丝线分隔的记录行 |
| 部分结果 / 无记录 | 页眉含「部分」「不完整」，或「没有符合条件」 | 页内（或单独）一行提示：琥珀图标底 + 原句 |
| 澄清 | clarification 事件 | 左侧 3dp 琥珀边线 + 问句 + 「还缺」列表（轮廓小标签） |
| 执行回执 / 结果 | receipt、execution_result | 状态条：20dp 圆形图标 + 一行字（成功：鼠尾草绿对勾；被拒：红色叉；已关闭：灰蓝锁；核对中：琥珀沙漏） |
| 错误 | error 事件 / 横幅 | 既有柔红底，前面加错误图标 |

### 账页

```
┌──────────────────────────────────────┐   纸页：白底（#FFFFFF），1dp #C5C8BB，圆角 12dp
│ ✓ 根据当前可信记录                    │   页眉：Label，Graphite，前置对勾
├──────────────────────────────────────┤   发丝线
│ (⇄)  zhy → whr             1.3833 CNY │   债务行
├──────────────────────────────────────┤
│ (🧾) 烧烤                  750.00 CNY │   消费行（图标为轮廓图形，非 emoji）
│        付款 小王                750.00 │   子行：Label，金额右对齐
│        分摊 小李                187.50 │
└──────────────────────────────────────┘
```

- 图标底：28dp 圆，`#EBE4D6`（Cream），图形 `#575449`；所有行类型共用同一个底，只换图形（债务：双向箭头；消费：收据；活动：文件夹；退款：撤销；预存：钱包）。
- 金额：App 既有数字体（Barlow Semi Condensed，tnum，`AmountSmall`），右对齐；币种用 `Label` 紧跟其后。金额字符串原样显示，不做舍入、不加千分位、不着色。
- **不推导方向**：服务端明确「不推导合计、汇率与方向」，客户端同样只显示「谁 → 谁」，不把「欠我 / 我欠」染成红绿。
- 行内文字允许换行；窄屏下金额不换行，名称列换行。
- 解析失败的行一律落回正文，所以任何内容都不会被丢掉。

### 动效

- 流式正文：修复结尾半透明，结束时一定完全不透明。
- 账页出现：纸页描边与页眉先出现，记录行依次淡入（每行 160ms，间隔 70ms，总长封顶 560ms），金额随行出现；只淡入，不位移。每条消息只播一次，历史重建不播。
- 状态条图标：新出现时 180ms 弹簧缩放（0.6 → 1），回应用户的确认操作。
- 系统关闭动画时：全部直接显示最终状态。

### 自查

- 第一版直觉是「每条记录一张圆角卡片 + 红绿箭头区分谁欠谁」：这是典型的 SaaS 卡片套装，而且红绿方向需要知道「我是谁」，服务端特意不给方向，客户端不该自作主张。改为一张纸页、发丝线分隔，颜色只用中性底；类型用图形区分。
- 第一版还有每种类型各配一种强调色：色彩太碎。收敛成两种语义色——琥珀（需要留意：澄清、部分结果、核对中）与功能色（成功绿、失败红），其余全部中性。
- 唯一的强调仍是草稿「落笔」；账页保持安静，不加阴影、不加渐变。

## 原则

1. 草稿像一张没签字的凭证：虚线、票头条、金额右对齐。这是整个面板唯一的强调。
2. 演示数据必须一眼可辨：Mist 票头条 + 文案「演示数据，不会记账」，绝不能和真实草稿用同一颜色。
3. 不装「AI 感」：无星星图标、无打字点动画、无头像、无渐变。
4. 状态用人话：`step` 映射为「正在理解你的话 / 正在读取账目 / 正在拟草稿 / 等你补充 / 需要重新登录 / 等你确认」等，一行文字。

## 动效

只保留用户触发的：面板打开/关闭（Sheet 自带），新事件追加时列表滚到底。不加入场淡入、不加打字动画。尊重系统「移除动画」设置（`Settings.Global.ANIMATOR_DURATION_SCALE == 0` 时滚动用 `scrollToItem` 而不是 `animateScrollToItem`）。

## 文案

- 空状态：「说一笔要记的账，或者问问谁还欠多少钱。」
- 输入框占位：「说一笔要记的账，或问谁还欠多少」
- 发送按钮：「发送」；取消进行中的回合：「停止」
- 澄清：显示助手的 `prompt`，输入框占位改为「补充：」+ 缺的字段中文名
- 确认按钮：「确认记账」，可点；飞行中显示「确认中…」并禁用；说明「确认后会立即记入账本。」
- 确认结果：
  - 202：草稿下方出现一行安静的回执「已提交执行 · 回执 3f2a9c1e」，执行中追加「执行中」；状态行显示「正在记账」。
  - `RECOVERING` 或 `execution_resolution=unknown`：回执与状态行一律「正在核对结果」，不出现「已记账」「没有记账」等成功/失败字样。
  - 501：按钮下方说明改为「执行暂不可用」。
  - 演示草稿（simulation）：按钮保持禁用，说明「演示数据只用于预览，不会写入账本。」
- 错误（按 `ApiErrorResponse.code`）：
  - `unauthenticated`：「登录已过期，请重新登录后再试。」
  - `forbidden`：「你没有这个活动的权限。」
  - `agent_disabled`：「助手已被关闭，可以继续手动记账。」
  - `rate_limited`：「说得太快了，稍等几秒再发。」
  - `dependency_unavailable`：「助手服务暂时连不上，稍后再试；手动记账不受影响。」
  - 网络失败：「连不上助手服务，检查网络后点重试。」
  - 其他：直接显示服务端 `message`（≤240 字）。

## 自查记录

- 初版用了「左右聊天气泡 + 头像 + 星星悬浮按钮 + 打字点」——换任何一个聊天助手都会得到这套，推翻。改为：助手回复无框直排、仅用户的话有底块；入口用笔记图标 + Graphite；状态改成一行人话。
- 初版草稿卡片是普通圆角卡片加阴影，与 App 其他卡片无法区分，属于卡片套装。改为虚线描边 + 票头条的「未签字凭证」，并让它成为面板唯一的强调。
- 演示与真实草稿初版同色，存在把演示当真的风险。新增 Mist 色专用于 simulation。
