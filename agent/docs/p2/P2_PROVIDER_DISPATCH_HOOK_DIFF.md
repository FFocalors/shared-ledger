# Shared P2 provider durable dispatch hooks

This change adds optional internal lifecycle hooks to the existing shared `LMStudioOpenAIProvider` path. The default v1/v2 `generate()` path is unchanged: it still serializes once, counts from those request bytes, uses the provider's existing one-slot semaphore and HTTP transport, and returns completion text as `str`. The change does not choose repairs, retry requests, refund Store budget, or prove that a remote model completed inference.

`LMStudioOpenAIProvider._generate_bound_body` now accepts `before_dispatch(actual_body_sha256, validated_measurement)` and `on_transport_result(observation)`, both defaulting to `None`. `before_dispatch` runs only after the typed counter request was reconstructed from the same immutable `body`, the trusted measurement passed validation, and the final enabled/started/closed check passed. It runs synchronously while `_state_lock` is held, immediately before creating the existing `asyncio.to_thread(self._transport, ..., body, ...)` worker. It may perform only a short same-Store compare-and-swap; it must not await, access auth/source/network, or reenter provider lifecycle methods. The digest is recomputed from the exact bytes that the counter and transport use.

An asynchronous callback, non-`None` return, or callback exception becomes the fixed sanitized `dispatch_hook_rejected` provider error, and no HTTP worker is created. This error does not prove that a callback did not commit before raising. Runtime must read the durable reservation/dispatch receipt before classifying known-no-dispatch or refunding; an unavailable or committed receipt remains unknown/consumed. If the dispatch callback succeeds but creating the HTTP task fails, the provider returns fixed `dispatch_worker_failed`; it does not refund or retry. The existing semaphore is released through the normal `finally` path. A callback-free call retains the existing task-creation behavior.

The observer receives only the frozen `LMStudioTransportObservation` value: strict integer HTTP `status`, nonnegative integer `body_bytes`, lowercase SHA-256 `body_sha256`, and optional timezone-aware `observed_at`. It never receives response bytes, content, prompt/messages, headers, token, or source rows. It runs after transport result shape validation and the configured response-size bound, before HTTP-status classification and completion parsing, so bounded 200/empty, length, and non-200 results can be distinguished. Invalid result shape and oversized body fail closed before observer invocation; no unobserved/truncated bytes are represented as a response receipt. Observer failure returns fixed `transport_observer_failed`, keeps provider health failed, and cannot return accepted completion text. All hook exceptions are sanitized; arbitrary exception text is not persisted or surfaced.

After `before_dispatch` commits, transport failure, cancellation, observer failure, task-creation failure, or process loss is not automatically treated as known-no-dispatch. The shared provider does not alter the existing checker/transport worker drain behavior: cancellation continues to wait for the same worker before releasing the concurrency slot. HTTP dispatch attempts, status/body metadata, nonempty completion, schema/guard acceptance, and durable task result remain separate Runtime/Store facts.

The new CPU tests exercise the actual shared `_generate_bound_body` implementation with injected fake counter and transport, including exact request/body equality and ordering, counter and hash failures before the hook, close/disabled paths, synchronous-hook enforcement, callback failure and gate reuse, committed marker followed by worker-creation failure, status/empty/length observation, oversize rejection, sanitized observer failure, strict observation metadata, and an Event-controlled post-dispatch cancellation that proves the same worker drains before a successor reaches the hook or transport. Existing affected provider/token and v2 prompt/provider/repair tests remain unchanged.

This is a provider-mechanism slice only. It does not change `P2Runtime`, Store, backend, API, settings/components, prompt providers, schema/contracts, or default routing. No real SDK, model, LM Studio, Supabase, external HTTP, database, Docker, or server was used. The new hook tests inject an in-process fake transport; the affected legacy read-provider regression suite also uses a disposable localhost HTTP stub.
