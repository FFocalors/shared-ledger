# P2 收口：已知限制一页（不影响训练，留待以后）

**日期：2026-10-20　裁定：停止 P2 绑定修复（R1-1…R1-6），P2 视为完成，转 P3b 待命。**

本文是 P2 的**收口页**：把所有仍未消除的限制集中成一张表，并逐条说明「为什么它不影响训练」，以及「什么情况下必须回头处理」。引用 P2 结论时只引本文与 [交付状态 R4](P2_DELIVERY_R4.md) 即可，不必再读修复建议。

## 一句话

P2 通过的是**本机隔离环境下的只读链路工程基线**；未消除的项分为「功能/范围限制」与「证据绑定缺陷」两类，**两类都不改变任何训练数据、模型输出或业务代码**，因此不阻塞训练，留待以后。

## 二、证据绑定缺陷（结论成立，复现性不足）

来源：[独立复核记录 R1](P2_BASELINE_CALIBRATION_REVIEW_R1.md)。**用户裁定：停止修复，登记为已知限制。**

| # | 缺陷 | 影响面 | 为何不影响训练 | 何时必须回头处理 |
|---|---|---|---|---|
| R1-1 | 执行 pin 绑定的是**本机工作树字节**，行尾与干净 checkout 不一致（干净 checkout 上 44/46 不匹配） | pin 只能当「这台机器当时那份字节」的指纹，不能当可独立复现的源码身份 | 训练数据与产物不引用该 pin；pin 只服务于 P2 自身的证据复算 | **任何外部/第三方需要复现 P2 证据时**（此时先规范化行尾或改哈希 git blob + `.gitattributes`，再重签） |
| R1-2 | 全量套件证据产自**脏树**（`git_head=0022b00`、非 clean），与 `3fcb2fd` 的字节等同属历史推断 | 「745 passed 对应 `3fcb2fd`」不可由 artifact 自证 | 套件结果当时为真，且不构成训练数据 | 同上，或需要把套件结果写进对外验收文件时 |
| R1-3 | 录制的 stdout SHA-256 不可从保存文件复算（`write_text` 二次换行产生 `\r\r\n`） | 哈希声明无效；文本内容仍可读、结论可核对 | 与训练无关 | 重跑证据时顺手改 `write_bytes` |
| R1-4 | 3 个迁移用例硬编码原始仓库绝对路径（`test_p2_v3_store_recovery_edges.py:1169-1172`） | 套件只在原始路径全绿；干净 checkout 实测正是这 3 条失败 | 属测试可移植性，非产品行为 | 有人在别处跑全量时 |
| R1-5 | leg 的 `expected_head_prefix` 只是调用方字符串，harness 从不 `git rev-parse` 校验 | 该字段不构成绑定；真实绑定来自 `manifest_sha256`（已逐步核对通过） | 无 | 重跑 leg 时删除或改为实测 |
| R1-6 | 证据目录保留 24 次未成功尝试（13 次 harness 缺陷、6 次已修缺陷复现、2 次预算耗尽、2 次模型协议不遵循、1 次模型未加载） | 已披露，不推翻四条 leg，但须与成功项一并引用 | 无 | 引用该目录时保持一并披露 |

## 三、P2 完成的口径（不要放大）

**成立**：四条证据 leg 的实质数值全部可从 artifact 复算——零模型闭环、真实模型闭环、两条身份恢复；接地端到端成立；身份恢复复用查询且不额外消耗额度；Turn 不再遗弃。全量套件在原始路径 + 两个新建 store 根目录的调用方式下为 `745 passed, 1 xfailed`。

**不成立**：可独立复现的源码身份（R1-1/R1-2）；组织意义上的独立评审（复核由产出方自审完成，root 会签栏仍空）；模型质量；云端；CAP；业务写入。

## 四、与「不影响训练」的准确边界

这句话的意思是：**未消除项不改变任何训练数据、模型输出、业务代码或默认装配**，因此不阻塞训练流程。

它**不**意味着：P2 可以作为「任何机器都能复现的正式验收证据」对外引用。若日后有人需要拿 P2 作外部验收依据，先做 R1-1/R1-2 的修复并重签，再重新出具记录。
