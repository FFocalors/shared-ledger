## New event-contract module

Add agent/app/p2_event_contracts.py. It imports the existing canonical AgentEvent/TurnPublicStatus types and existing candidate P2 DTOs, without editing either contract module. It is not imported by API composition and does not install a route.

The module defines:

- Strict poll query DTO with after_seq: StrictInt >=0 (default 0) and limit: StrictInt 1..500 (default 100).
- Strict P2EventPollResponse with api_version literal 1.0.0, the fixed P2ProtocolVersions tuple, existing TurnPublicStatus, after_seq, up to 500 projected events, next_after_seq and has_more. It verifies the exact tuple, monotone unique event sequences, sequence strictly after the requested cursor, correct empty-page cursor, and has_more/cursor shape.
- P2ProjectedEvent with Store sequence, timezone-aware created_at, canonical AgentEvent and optional candidate_output. The AgentEvent seq must equal the row seq and occurred_at must be timezone-aware. If candidate_output is present, the paired canonical event is a harmless status event so the legacy v1 poll never returns candidate answer text without its qev/card sidecar.
- A strict extra-forbid P2CandidateOutput union for answer, clarification and proposal recognition only. It has no read event, write, preview, confirmation, execution, proposal-card, source UUID or continuation fields. It never uses a fifth profile label.
- P2EventObservation, a typed historical qev summary preserving operation, source kind/version, observed_at, source financial-version map, returned/matched counts/totals, page count, has_more/truncated, source-query completeness separately from model-projection completeness, coverage/version/uniqueness flags, zero classification and explicit derived result_state. It carries the existing qev query_digest/body_digest/projection_digest under their existing names. `body_digest` retains its existing meaning and is not claimed to be the raw HTTP body hash. No current/fresh-now field is present.
- P2FactCard, a strict wrapper binding exactly one existing P2Fact union member to its QueryEvidenceRef. The fact's embedded qev must equal the wrapper qev. This preserves each of the seven discriminated fact variants, including nullable original values, separate original/base amounts and currencies, signed amounts, roles and source financial versions. Values are not converted, netted, summed, rounded, inferred, or fetched by a renderer. Opaque refs stay opaque; raw source UUIDs, source_ref, query_ref, result_ref and page continuation refs are forbidden by the typed schema.
- P2AnswerOutput with kind, basis, model narrative text, distinct citations, one observation per cited qev, and up to 256 typed fact cards. For non_business_general, citations, observations and cards must all be empty. For fresh_read_receipts, citations are nonempty; observation qevs exactly equal the citation set; each card qev is cited; duplicate fact identities are rejected. A cited qev may have zero facts for a complete-empty result. Partial results retain explicit partial state and only their accepted cards; they cannot be represented as exhaustive zero.
- P2ClarifyOutput and P2ProposalRecognitionOutput with the reviewed R1/R2 bounds. Proposal recognition remains intent-only.

The module exposes `project_p2_backend_result(result) -> (P2EventObservation, tuple[P2FactCard, ...])`, `build_p2_answer_output(decision, accepted_results=())`, and `build_p2_candidate_output(decision, accepted_results=())`. These helpers strictly revalidate serialized DTOs before projection. They do not make a source call and do not establish authorization or receipt currentness. Before publication, Runtime must supply an accepted result from the same owner/Turn/input/generation/current-scope context, prove the actual backend capture and per-GET receipt chain, and commit the typed snapshot, receipt references and event proof atomically. Hash/DTO presence is not proof of Auth or RLS.

Zero/partial derivation is strict: complete_empty requires zero matched facts, zero matched_total when present, backend_zero or post_filter_zero, complete source query and model projection, no more page and no truncation, plus accepted contiguous/unique/source-version-fenced coverage (and stable total when a total is reported). backend_zero requires no source rows; post_filter_zero may have returned source rows but has no matched facts. complete_nonempty requires at least one matched fact and complete source and model projections. Every other combination is partial_or_unknown. A full source query with a capped model projection is not model-complete, and an empty visible page does not prove empty source data.

The separate D-only schema artifact is generated from these DTOs for review and bound to the existing frozen OpenAPI hash. Frozen OpenAPI files and exporter are not changed. No HTTP route or default-on behavior is added.

## Shape parsing and trusted read/answer guard

Minimal changes to agent/app/p2_read_contracts.py add one reusable strict shape parser, `parse_p2_decision_shape`. It parses the supported read/answer/clarify/propose JSON union with duplicate-key rejection, NaN/Infinity and overflow-to-infinity rejection, strict types, and discriminator validation. It makes no authorization decision. `parse_p2_read_request` delegates to this parser and only accepts read request variants.

The existing parse_p2_decision(payload, context) remains the authorized entry point. It must call the shape parser, revalidate both decision and private context from serialized JSON to defeat model_copy/model_construct bypass, and then apply the existing trusted guard. It remains a required context argument. No existing caller silently switches to shape-only parsing. The first-read flow is: shape parse criteria -> Runtime resolves trusted current scope and mints exact operation/criteria-bound grant -> Runtime builds trusted private context and calls the authorized guard -> backend dispatch. Shape-valid read JSON alone cannot dispatch a GET.

Private `P2QueryAuthorizationBinding(query_evidence_ref, receipt, grant)` entries are added only to internal `P2IntentContext`, never to `P2ModelContext`, model requests, or public events. Each bounded entry binds one qev to exactly one `P2FreshQueryEvidenceRef` and one `P2SourceAuthorizationGrant`. Static validators require the same qev, owner/Turn, input sequence/digest, generation, operation, exact criteria digest and scope, with timezone-aware grant expiry and receipt observation/expiry. The context rejects duplicate receipt refs or duplicate binding qevs. Verified-scope bindings must use that exact current verified scope. The only unscoped case is Activity discovery. All bindings used by one answer must share owner, Turn, input, generation and current scope; cross-scope or mixed-identity bindings fail.

Keep the legacy single-grant path for existing single-read and single-query answer callers. If no per-qev bindings are supplied, existing grant/receipt checks stay in force. The initial R1 implementation required citations to equal the complete binding qev set; the cited-qev subset delta below supersedes that requirement. Each cited qev maps once to its own fresh receipt and grant, and that cited grant/receipt must be unexpired and bound to its own operation and criteria digest. Each receipt scope must equal the current verified scope; no-scope answers may cite only Activity discovery. A single grant cannot authorize different operations or criteria. Do not weaken prior negative cases.

The private DTO map establishes structural consistency only. Trusted Runtime remains responsible for confirming that each grant was freshly minted from the authenticated principal and current source permission, every receipt belongs to an accepted actual query, the raw-byte/typed-source/projection chain is intact, source version and financial versions are current, and the scope/owner/Turn/input/generation bindings have not changed. This per-qev map solves the private DTO's one-grant-per-answer-criteria limitation for same-scope multi-query answers; it does not allow cross-scope answers or prove authorization. The Runtime must not persist bearer tokens or live grant capabilities. A qev, digest, timestamp or P2Fact card is not authority.

## Cited-qev subset guard delta (2026-10-14)

The implementation direction requires one exact, fresh, same-scope authorization binding for every cited qev; it does not require an answer to cite unrelated queries that happen to be present in the same turn context. The current guard therefore accepts a nonempty citation subset of the context's per-qev bindings. Each citation must still resolve to exactly one matching receipt and grant, and operation, criteria digest, scope, principal, owner Turn, input sequence/digest and generation checks remain per cited qev. Missing/duplicate mappings, mismatched or cross-scope grants, stale cited evidence and expired cited grants remain rejected. The primary grant must still be represented among the mappings; when per-qev mappings exist, its expiry is checked only if that qev is cited. The legacy no-mapping single-grant path retains the original primary-grant expiry check.

Uncited receipts and grants are not freshness requirements for an answer and are not projected into its public observations or fact cards. The event output builder continues to require the accepted result qev set to equal the answer citation set; callers must pass only the accepted results for cited qevs. This lets a valid expense-only answer ignore an unrelated debt receipt without letting the expense grant authorize the debt query.

This is a private candidate guard/test delta only. It does not change the public model context schema, add authority, relax same-scope/current-turn binding, or establish Runtime/Auth/currentness. The previous R1 manifest remains immutable history; this delta is recorded in `D:\AI\runs\shared-ledger\p2\p2-event-contracts-subset-grant-delta-20261014-r2`.

## Projection result-state consistency delta (2026-10-14)

The projector and public observation validator now use one pure result-state rule. A result is coverage-complete only when source and model projection are complete, there is no continuation or truncation, and the range, source-version fence and uniqueness checks pass. A stable total is required only when `source_total` is known; `matched_total` is the filtered match count and does not imply that the server's source total is known. If a known source total is not stable, the result remains partial. `unknown_or_partial` always remains partial regardless of otherwise-positive coverage flags. `complete_empty` requires a fully covered result and an explicit `backend_zero` or `post_filter_zero` classification; `complete_nonempty` requires fully covered `nonzero` evidence. Shape-consistent output is not authorization, source-acceptance, or currentness proof.

The tests use actual typed `P2ReadBackendResult` instances accepted by the source DTO. Before the helper change, the unknown-zero case reproduced a `P2EventObservation` validation mismatch: the helper selected complete-empty while the validator required partial. A second red case reproduced the same mismatch for `source_total=None`, `matched_total=0`, and `stable_total_verified=False`. After the shared rule was added, tests also confirm a known but unstable source total stays partial and a complete post-filter zero with unknown source total is complete-empty. The initial full-suite attempt after the fix exposed a test-only `NameError` in the known-source case; that fixture was corrected, the failed output was preserved, and the final focused run passed.
