# P2 v3 protected event DTO candidate

This is an unassembled, display-only DTO candidate. It adds no route, OpenAPI entry, Store query, Runtime behavior, canonical event, or protocol version. The public types stay pinned to the reviewed tuple `3.0.0 / 2.1.0 / 2.1.0 / 2.0.0` and the four existing decision semantics: answer, clarification, read result, and proposal intent. The two answer bases remain fields on the answer semantic.

The candidate uses the canonical `StatusEvent` as the only event-row input. It does not accept the wider canonical `AgentEvent` union or the v2 projected event. A page cursor follows ordered canonical status sequences; sidecar rows may be absent for a status event, and gaps in sidecar-bearing sequences are valid. A sidecar with no status row in the same supplied page, a repeated sequence, or a different private owner/Turn/profile/tuple fails closed.

`P2V3PrivateSidecarBinding` is private assembly input and is not serialized in `P2V3EventPollResponse`. It links an output to its owner, Turn, and canonical sequence, then carries a separate `history_gate` bound to the exact context reference/digest, generation, read epoch, and text digest. Private UUID locators and proof IDs are never part of the public response. The link and gate are shape checks; they do not prove that a database transaction, Auth identity, membership, child scope, or source read was real.

The gate has three paths. `non_business_general` is the source-free answer path and forbids QEVs, facts, labels, and actor metadata. `source_free_control_intent` admits only a server-controlled clarification or an intent attributed to the original user input. That path has no phantom scope receipt, and it requires an empty private `source_projection_kinds` classification. The classification must be derived from the exact server-built model context, including facts, QEVs, current-actor bindings, display labels, expense titles, and other source history; absence of financial QEVs by itself never makes output source-free. A scope-gated output carries private scope/activity locators plus per-QEV, per-fact, and/or metadata proof bindings. Markers for labels, expense titles, and current-actor projections require the corresponding private metadata proof. A clarification or proposal can be scope-gated even when it has no financial QEV or public label, which covers source-derived names in text. The gate binds the displayed text digest and maps its private text scopes to source metadata or query proofs.

Metadata-only output may be scope-gated at read epoch `0` when no financial read has occurred. The gate still carries the matching private scope and source-metadata proof; the epoch is copied from the output and is never invented as a substitute for provenance.

Public labels and `current_actor` values must match private metadata proof keys including entity kind/reference, source reference, scope, source kind, and public receipt reference. Each public QEV must match one private QEV proof. Each included fact must match a private row binding. The closed fact-reference map follows the seven reviewed DTOs: `activity_ref`, `expense_ref`, `debt_ref`, `refund_ref`, `account_ref`, `usage_ref`, and `return_event_ref`. A private UUID change alone does not prove the corresponding database row; the future caller must obtain these private inputs from a trusted same-snapshot Store read and then make a new current-principal membership/child check for every source-bearing sidecar. A stored history item is never an authorization receipt for a later poll.

Historical reads use the new `P2V3HistoricalReadPayload` and `P2V3HistoricalReadPage`, not a persisted live `P2ReadBackendResult`. `project_live_p2_read_result_for_history` first revalidates the exact live result and maps its operation, query evidence, facts, completeness, `has_more`, page index, and coverage fields. The historical page has no `next_page_ref` member, so a continuation capability cannot be replayed from history. `has_more` remains the actual live value; it is not forced false. An incoming historical `next_page_ref` is an unknown key and is rejected. Source completeness, model-projection completeness, `has_more`, and the existing zero classification remain independent and are copied as supplied.

The parser rejects duplicate JSON keys, non-finite or floating JSON numbers, unknown fields, mixed tuples, implicit nullable QEV defaults, and malformed private linkage. It validates structure only. It does not grade answer text, establish source truth, refresh Auth, or authorize a read. A future protected GET must retrieve canonical status events and private sidecars in one owner-bound database snapshot, authenticate the current caller, and freshly verify every required scope and child membership before serializing any protected output. If a current membership check cannot be completed, the caller must omit/fail the protected output rather than rely on the historical sidecar.

The focused tests use synthetic DTOs only. They cover source-free activity-selection clarification without phantom scope; metadata-only source-derived clarification at read epoch `0` without a financial QEV; missing metadata proof rejection; actor and public-label linkage; exact financial string preservation and private fact-row binding; all seven fact-reference field names; strict cursor/tuple/extra-key checks; status-only rows and sidecar sequence gaps; owner/sequence mismatch; and a `has_more=true` live read result whose continuation token is absent from historical serialization while page index and coverage values remain unchanged. These tests do not exercise application assembly, HTTP, SDK, Auth, Runtime, Store, RLS, or current membership.

## R2 scope and collection proof correction

R2 is an additive private-proof correction; it does not change the public DTO, tuple, routes, or existing protocol version. A single Activity may have multiple child-scope locator bindings. Each scope reference remains unique, and all scope bindings for the same Activity must resolve to the same private Activity locator; a private Activity locator cannot alias two Activity references. This supports an expense/debt scope together with a current-actor proof for that same Activity.

Scoped `read.activities` remains valid through the scoped QEV proof. Its private scope must identify the exact Activity; matching references and included `ActivityFact` rows cannot point at another Activity, and the private row locator must match the Activity locator. The source R4 adapter includes the scoped Activity snapshot's `financial_version` in QEV for this operation too. The private history check therefore accepts that QEV version when it names exactly the bound Activity, permits the field to be absent for compatible results, and rejects a foreign Activity or multiple versions. It does not derive this QEV fence from `ActivityFact.context_version`, which is a separate field.

Unscoped `read.activities` uses `P2V3PrivateActivityCollectionQevProofBinding`, not a fabricated scope. The binding is a discriminated sibling of the scoped QEV proof and carries the exact public query descriptor, a private collection query/locator pair, one private membership locator/proof for every `matching_fact_ref`, and per-included-Activity fact-row links to those same row locators. It contains no scope reference or credential. The private identifiers are lookup/audit inputs only: a future Store poll must reauthorize the current principal against the original Activities collection descriptor and freshly verify each surfaced Activity membership. Activity labels and current-actor metadata still require separate metadata evidence and their actual scope; collection discovery cannot authorize those projections.

An empty Activities collection is not inferred from an empty page. `backend_zero` is accepted only with complete source and model coverage, no continuation, zero source/returned/matched counts, and zero matched total. `post_filter_zero` is accepted only with complete source and model coverage, no continuation, known nonempty source rows, and zero matched rows. A complete empty query classified only as unknown is rejected. An `unknown_or_partial` empty page remains displayable as partial when the QEV says source or projection coverage is incomplete; it cannot support a complete-empty statement.

For financial facts, the private QEV binding now mirrors the full public query descriptor (query/result/source/criteria references and digests), not only its source. A scoped QEV is checked against one pinned Activity scope and its financial version; every included fact must match the QEV reference and version and be present in the QEV's `matching_fact_refs`. Expense titles need exact private expense-row and scope proof under the `expense_titles` classification; that does not require an unrelated Activity display-label proof. These shape checks still do not establish that a locator or fact value is true: the future Store must compare private row identity, exact source values, and financial-version linkage against its trusted same-snapshot source read.

The R2 candidate is not assembled or authorized for Runtime/API use. Its source-contract dependency has an independently authorized nullable-timestamp correction in progress; the R2 final source/test hashes and test result must bind the frozen current contract source and its review, or explicitly remain pending until that freeze. No old R1 contract hash is claimed as current evidence for that corrected source.

## R3 scoped Activity financial-version compatibility correction

The R2 rule that scoped Activity reads carry no financial version was incompatible with the frozen R4 source adapter. `_v3_build_result` fences every scoped operation from the Activity snapshot and emits that snapshot's `financial_version` in `P2QueryEvidence.financial_versions`, including scoped `read.activities`; the `ActivityFact` itself exposes a distinct `context_version`. The private event check now accepts an optional single QEV financial version only when its `activity_ref` equals the private scope's exact Activity. It rejects a foreign Activity and multiple entries. It never treats `ActivityFact.context_version` as a financial-version source.

The R3 CPU regression obtains a scoped Activities result from the actual R4 adapter using its existing synthetic source transport, then calls the event history projector and validates a private scope/QEV/fact-row binding. A second case replaces only the QEV financial-version reference with a foreign Activity and verifies that the private gate rejects it. This checks the real adapter-to-history shape while keeping transport and all source rows synthetic; it is not evidence of Store authorization or production source truth. The public tuple and DTOs are unchanged.
