# P2 v3 prompt and shared-provider facade candidate

This is an opt-in, unassembled v3 prompt/prepared/provider slice. The four new files are `p2_read_prompt_v3.py`, `p2_read_provider_v3.py`, `test_p2_read_prompt_provider_v3.py`, and this document. Existing v1/v2 code, the accepted v3 contracts, the shared provider, Store/Runtime/backend/API, settings, and exports remain outside this change.

The prompt module uses the accepted profile `p2.read-paged-prepayment-refund.v3-candidate` and the exact four-version tuple `3.0.0 / 2.1.0 / 2.1.0 / 2.0.0`. It has separate prompt, wire-config, provider-facade, and response-schema names. It builds a canonical UTF-8 chat-completions body with the fixed 8192 context, 6144 input, 768 output, 512 schema margin, temperature zero, one request, streaming disabled, and strict v3 decision JSON schema. Normal messages are system/user; the only repair form is the fixed server-authored system/system/user triplet from `p2_format_repair`, identified and hashed without including previous output or arbitrary error text.

Preparation accepts a strict public `P2ModelContext` and transient private `P2IntentContext`. `validate_p2_clarification_projection` checks that their generation, input sequence, classification, scope, and safe pending clarification projection agree before rendering. Only the public context enters the user message; private principal/turn identifiers, input digest, grants, receipts, and private UUIDs are not serialized. `P2V3PreparedRequest` binds exact body bytes, schema/context/request digests, repair digest, candidate tuple, model, endpoint, prompt/provider/wire versions, and a fingerprint. Strict validation reconstructs the canonical request and rejects altered bytes or mismatched bindings.

`P2V3ReadProvider` wraps the existing `LMStudioOpenAIProvider`; it adds no transport, counter, semaphore, parser, retry loop, or scheduler. The facade rechecks the public/private projection and the current shared provider model, normalized endpoint, temperature, output cap, structured-output setting, schema selection, and concurrency against its constructor-bound config before calling the shared body path. It forwards the exact prepared bytes/hash and optional dispatch/response hooks. One facade call can count and dispatch once; it returns raw completion text for a later v3 shape parser and Runtime guard. It does not execute a source read or authorize an answer.

The prompt treats input text, recent messages, source names/titles, display labels, and fact text as data rather than instructions or authority. Business answer citations must refer to allowed fresh query evidence with a matching public qev; metadata receipts cannot stand in for financial citations. It preserves exact amount lexemes, currencies, direction, timestamps, nulls, source versions, and the distinct source/model completeness and pagination flags. `backend_zero` may support a no-match statement for the exact query scope/criteria when visible completeness and coverage flags are complete. `post_filter_zero` may support a no-match statement for the queried scope/criteria after post-filtering only when the same complete coverage holds, while retaining its distinction from `backend_zero`; it never supports a claim that the unfiltered source table is empty. `unknown_or_partial` or incomplete coverage cannot support a complete-empty claim. It forbids model-side conversion, totals, netting, or invented values. Runtime remains responsible for current source authorization, freshness, and any selected operation-specific grant.

Static shared-provider drift review: `LMStudioOpenAIProvider._generate_bound_body` builds its token request from `_config` before awaiting the concurrency gate, awaits the token checker, validates the measurement, then reads `_config.endpoint_url` again when creating the transport worker. The lifecycle lock does not guard external replacement of the `_config` reference, so a port change can leave the counter bound to the original origin while a later POST uses a replacement endpoint. The v3 facade always supplies a short synchronous dispatch wrapper, even when Runtime gives no callback. After the shared gate and counter complete, that wrapper revalidates the current model/endpoint/temperature/output/schema/concurrency binding, the exact prepared body hash, and the measurement model/origin before invoking a caller callback. It returns the caller's original callback result to the shared provider's hook validator, preserving the shared contract that callbacks are synchronous and must return `None`; non-`None`, awaitable, and exception outcomes are rejected and sanitized before transport dispatch. CPU tests block the fake counter to prove config drift yields one count and no caller hook, observer, or POST, and separately prove that invalid callback return values invoke the caller once but yield no POST. Runtime's callback should capture the prepared body hash, normalized origin, model id, profile/version tuple, generation/input sequence/turn, and reservation identity, then perform its Store dispatch CAS synchronously after the wrapper's checks. This rejects drift visible at the hook boundary; because config replacement itself is not synchronized by the provider lock, it cannot promise atomicity against reassignment after the wrapper check and before worker creation. A full atomic guarantee would require a later shared-provider snapshot/config-lock change, outside this slice; no shared-provider source was modified here.

The CPU tests cover non-business, pending-scope clarification, and verified financial metadata contexts; preserve Unicode names/titles, exact original/base amount lexemes and timestamps; reject public/private generation/input/provenance/pending mismatch, altered prepared body/hash, wrong tuple, closed feedback misuse, post-preparation provider-config drift (including a different allowed loopback port) before count/hook/POST, and non-`None`/awaitable dispatch callbacks before POST. They exercise all seven v3 read-query shapes and continuation shape, strict normal/repair message forms, exact golden body/schema hashes, and one shared fake counter → dispatch hook → fake transport flow for normal and repair bodies. No read decision is authorized or sent to a backend.

All new tests use an injected in-process fake counter and transport. The implementation is disabled by not being imported or registered by the application. No SDK, model, LM Studio, service, external network, database, Docker, Supabase, or Git operation is part of this candidate.
