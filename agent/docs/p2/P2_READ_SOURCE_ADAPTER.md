# P2 paged read source adapter (isolated candidate)

Status: CPU-only candidate for `p2.read-paged-prepayment-refund.v2-candidate`, with versions `api=2.1.0`, `semantic=2.0.0`, `operations=2.1.0`, `trajectory=2.0.0`. The module is not imported by application composition, is not registered as a production backend, and does not change the canonical v1 contracts or RPC behavior. This note records source mapping and local fake-transport evidence; it does not establish live Auth, RLS, database grants, or production acceptance.

## Read path and limits

`P2ReadBackendAdapter` accepts only the seven typed read operations in `p2_read_contracts.py`. It uses fixed GET table/select/order plans and the current user bearer token with the configured publishable/anon key. It rejects private-schema sources and arbitrary RPCs. Server-issued single-use grants bind the operation, criteria, scope, owner, Turn, generation, claim, and accepted input. Entity IDs remain in Turn-local bindings; public refs are random and do not encode source UUIDs.

User criteria are locally applied after scope-authorized source retrieval. The evidence stage is therefore `scope_only`; the adapter does not claim server-side criteria pushdown. Source rows must have contiguous, exact `Content-Range` pages and a stable total. Each source table is capped at four pages of 16 rows (64 rows), a model page exposes at most 16 facts, and a Turn is capped at 48 GETs, 20 seconds of active backend work, 4 MiB of response bodies, and a 240-second absolute Turn deadline. Scope resolution, source parsing, joins, and projection consume the active backend-time budget. Empty source results are authoritative only after an exact zero total; a locally filtered empty result is `post_filter_zero`. Unknown debt original currency blocks a currency-filtered zero claim.

Every GET is charged to the Turn before dispatch. Its transport timeout is the minimum of the caller's existing timeout, remaining exact active-backend time, and remaining absolute-Turn time; its response cap is the minimum of the configured per-response cap and remaining cumulative bytes. A request-local deadline aborts the request control at that clamped timeout. The response body is charged even when a fake or broken transport violates the cap, and that response is rejected before capture or parsing. Unknown transport consumption remains a failure and prevents later dispatch. Fractional milliseconds are retained internally so repeated budget checkpoints do not truncate cumulative time.

Successful reads and grant resolution pass a final budget fence after scope checks, parsing, joins, and typed projection. The fence charges the final active-work interval before the operation returns. A failed continuation keeps its nonce consumed and marks the prior query stale; neither the old result nor a partly refreshed result is returned as current. Failure and cancellation paths preserve the triggering exception while retaining known or unknown request cost.

Continuations are single-use. The adapter checks current Turn claims and scope, consumes the supplied page token before doing more work, rereads the original query from source offset zero with the current verified credential, repeats the joins and source fences, and compares the new receipt bindings to the accepted query. A changed row set, membership, scope, or financial version makes the query stale; cached facts are not returned. The same in-memory `P2ReadTurnState` must span the Turn so retries cannot reset budgets. This candidate does not persist that state or restore it across process restart; a future runtime must perform fresh authorization and a complete source reread before it can create new current evidence.

## Operation source map

| Operation | Fixed public sources | Projection and boundary |
|---|---|---|
| `read.activities` | `activities`; explicit `activity_members` check for visible rows | Status and name criteria are local. Deleted activities are excluded. Unscoped listing is a point-in-time discovery result, not a financial snapshot. |
| `read.expenses` | `expenses`, then `payments` and `splits` for the returned expense IDs | Source rows are limited to current authorized ledger units and non-deleted expenses. Date, title, and participant criteria are local. Payer and split roles, signed original amounts, signed base amounts, and currencies stay distinct. Child participant configuration is rechecked. |
| `read.debts` | `expense_debts`, then linked `expenses` | Uses the candidate source variant `expense_debt_line`; preserves debtor, creditor, expense, ledger unit, and direction per row. Original amount and currency remain independently nullable; base amount/currency remain separate. It does not replace or reinterpret the canonical `list_settlement_options` RPC, aggregate rows, net directions, or convert currencies. |
| `read.refund_events` | Activity-scoped `expenses`, plus public parent `expenses` referenced by `original_expense_id` | Activity scope only. Negative original amounts are retained with their sign. A visible parent is checked for same Activity, ordinary positive parent shape, currency, and FX metadata; only the opaque parent ref and lineage status are projected, with no parent amount/title. The private refund-marker table is not read. A refund with no parent is marked unverified; a referenced but unreadable parent is marked unavailable. Neither is represented as verified lineage, and no refund recipient is inferred. |
| `read.prepayment_accounts` | `prepayment_accounts` | Activity scope only. Stored balance and account currency are read as source values; the adapter does not derive balances from transfers or usages. |
| `read.prepayment_usages` | `prepayment_usages`, joined to `prepayment_accounts`, `expense_debts`, and non-deleted `expenses` | Activity or authorized child scope. Child discovery does not require an expense hint: every usage must join through debt and expense to the selected ledger unit. An optional expense hint is rebound and checked against that unit. Amounts and currencies are kept in their source fields; no netting or FX is performed. |
| `read.prepayment_return_events` | Activity-scoped `transfers` and `transfer_components` | Activity scope only. Requires a live `prepayment_return` transfer, a matching return component and amount, and active same-Activity participants. These tables do not provide an account foreign key, so the DTO does not infer one. |

The source map follows the public table definitions and business constraints in `supabase/migrations/20260830115348_expense_core_schema.sql`, `20260830191659_backend_debt_projection.sql`, `20260831034645_backend_settlement_transfer.sql`, `20260831055425_backend_prepayment.sql`, `20260923022250_business_logic_finalization.sql`, and `20260923032928_refund_limits_and_legacy_rpc_permissions.sql`. Source review does not substitute for runtime authorization: fake transport tests cannot prove the deployed role’s table grants or RLS policies. In particular, the adapter must remain fail-closed if a required public join is unavailable or incomplete.

## Store-backed budget port checkpoint (2026-10-15 UTC)

The owned synthetic admission fixture uses this implementation rather than a copied test-only budget port. A GET is reserved before dispatch and receives a durable dispatch marker; only a confirmed pre-marker failure is released as `known_no_dispatch`.
