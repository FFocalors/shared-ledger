## Adapter and typed input boundary

`agent/app/p2_model_provider.py` implements `LMStudioOpenAIProvider`, `LMStudioOpenAIConfig`, `P2ProviderHealth`, and sanitized `LMStudioProviderError`/`LMStudioProviderErrorCode`. `agent/app/p2_token_budget.py` defines `P2TokenBudgetChecker`, `P2TokenBudgetRequest`, `P2TokenBudgetMeasurement`, `P2TokenBudgetPolicy`, `P2ModelArtifactBinding`, and optional `LMStudioSDKTokenBudgetChecker`.

The provider's structural `PromptEnvelope` accepts the unchanged `c.ModelContext` plus bounded `repair_feedback`. Runtime/Harness supply typed Pydantic `P2PromptEnvelope`, including optional provenance, expense supplements, and typed reference labels. The provider serializes the full typed envelope. It rejects arbitrary `Mapping`, extra Pydantic fields, UUID values/literals, token-identity fields, and tested common Bearer/JWT-shaped credentials. This is defensive validation, not general secret detection: the Runtime must prevent user/Turn/business UUIDs and credentials from entering the envelope and keep real UUID bindings private. The unchanged output schema is `c.SEMANTIC_DECISION_ADAPTER.json_schema()`; no canonical v1 schema was modified for the provider.

The system message lists the four existing semantic kinds and requires current, complete, correctly scoped provenance for grounded financial answers. Missing/stale metadata requires read/clarification; no metadata may be invented. Harness remains responsible for semantic parsing, binding checks, and at most one syntax repair. The provider does not treat a valid JSON schema or HTTP response as a successful task.

## OpenAI-compatible transport and limits

The implementation uses the OpenAI-compatible `POST /v1/chat/completions` route over an explicitly allowed local HTTP origin. It never silently switches to LM Studio native REST, probes the catalog, or starts/loads/unloads/kills a model. `start()` and `health()` are local state operations; actual generation makes a single POST, follows no redirects, and does not automatically retry. Cancellation/timeout holds the single concurrency gate until the owned request worker has truly terminated; a queued request rechecks closed/started/enabled state before dispatch.

Runtime `Settings` defaults are `provider_mode=disabled`, `p2_lmstudio_enabled=false`, and `p2_token_budget_enabled=false`. In P2 mode, provider enablement and token-budget checker configuration are explicit. If the token checker is absent, the provider fails closed with `input_budget_unverified`; it does not send a generation request. Production settings keep concurrency at 1, timeout at 30 seconds, output cap at 768, context at 8,192, maximum input admission at 6,144, and schema safety margin at 512 tokens. Input/request byte caps remain separate defensive bounds; bytes are never called tokens.

`LMStudioSDKTokenBudgetChecker.measure(P2TokenBudgetRequest)` is the optional live admission path. Before a POST it:

1. Verifies the absolute selected artifact path, SHA-256, size, stat signature, model key/path, explicit API origin, and configured context.
2. Uses a request-owned helper subprocess with LM Studio SDK 1.5.0 to look up the already-loaded exact model, apply its prompt template, and count the formatted prompt and response-format schema separately. The SDK receives the same API authority as the provider endpoint. It never uses JIT model loading and performs no inference.
3. Adds the separately counted schema and 512-token safety margin; rejects unverified, mismatched, or over-limit requests before POST. It checks the loaded model identity/context again after counting.

The total measurement deadline is five seconds and includes the cold artifact hash. Because hashing the 2.7 GB selected model can take close to that bound, a first cold measurement may fail closed; the operator may perform the explicit file-only artifact verification step before a separately approved request. The verified binding is cached only in process memory and every measurement rechecks the resolved path/stat identity. A timed-out helper is the only process terminated by cleanup; it can take up to a one-second cleanup grace after the measurement deadline. Normal logs never receive prompt, response, token, or SDK error contents.

This SDK count is a conservative admission estimate: its template count is plus an explicit schema count and margin. It does not prove LM Studio's endpoint accounts for structured schema exactly this way or that endpoint usage will equal the estimate. `max_output_tokens` is the server-side generation cap. For a context of 8,192, the provider separately enforces `budgeted_input_tokens <= 6,144` and `budgeted_input_tokens + requested_output_tokens <= 8,192`; an absent, failed, or changed counter binding fails closed.

## Internal health

`P2ProviderHealth` is separate from the frozen P1 `ports.ProviderHealth`, whose `inference_available` remains `Literal[False]`. An enabled new/started provider reports unavailable with `reason=not_tested`; configuration alone never reports ready. After a nonempty assistant response with valid OpenAI response framing and `finish_reason=stop`, the provider records a last success and reports provider-level ready. A later provider/parser/transport failure returns it to unavailable. This state does not verify P2 semantic schema, Harness binding/rendering, task correctness, model quality, or backend access. Root approved the internal P2 health mapping, and the Runtime/API consume this separate P2 provider state through existing internal health surfaces. The frozen canonical OpenAPI and P1 provider-health model remain untouched.
