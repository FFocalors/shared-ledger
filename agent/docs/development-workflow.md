## 1. 总览与时间线

核心原则一句话：

> **工程线（P）用 Mock 假模型往前赶，绝不等训练；训练线（T）只在关键路径上被硬件和模型能力卡。两条线在 P3b+T3 汇合做 go/no-go 门，门没过绝不写 UI。**

```
现在 ── P0/T0（能力映射 + 资产盘点 + 最小环境验证）
         │
         ├── P1（骨架·Mock）── P2（真实只读）──────────┐
         │        │                                    │
         │        └── P3a（Mock 写路径）────────────────┤
         │                                             ↓
         └── T1（协议冻结）── T2（针对性训练）── P3b+T3（联合·go/no-go 门）
                                                        │
                                                        ↓
                                             P4（App 接入）→ P5/T4（逐项扩展）→ P6（首版验收）
```

依赖关系速记：

- P0 能力映射完成 → 即可开 P1（不等 P0 的硬件验证）
- T1 协议冻结 → 是 P1 骨架的 Schema 输入（协议先定、骨架后搭）
- P1 稳定 → 开 P2；P1 完成 → 即可开 P3a（Mock）
- P2 的「未训练基线」+ T1 + Teacher 可用 + 4B 导出链通 → 开 T2
- P3a 完成 + T2 出候选 → 联合 P3b+T3
- P3b+T3 通过 → 开 P4（**此门未过，绝不写 P4 的 UI**）

## 6. 顺序与并行规则

1. **可并行的三条腿**：P1→P2→P3a 是纯工程腿（用 Mock）；T1→T2 是训练腿；两者互不阻塞，可同时推进。
2. **不并行的**：T2 依赖 P2 基线和 T1；P3b+T3 依赖 P3a 和 T2；P4 依赖 P3b+T3。
3. **一个能力一个验收单元**：P5/T4 阶段按 CAP 逐项推进，退款、外币、预存、结算、归档各是一个可验收单元，不同时铺开。
4. **旧资产不覆盖**：三次训练 run、旧六类协议、旧三档 Scope、旧 test/hard_test 只作历史参考；跨版本复用必须显式转换、重新审核、重新哈希。
5. **验收不以「模型说成功 / Mock / loss 下降 / JSON 可解析」为准**：写能力看「未授权写入=0、未确认写入=0、重复效果=0、结果可追踪」；语义质量看「有预设门槛的独立评测」。

## 7. 阶段验收速查（原文口径）

**P 线通过条件（摘要自指南）**

- P0：核心路径真实入口可定位；未知项有具体调查任务；没有把缺失功能写成已完成。
- P1：模拟查询/澄清/提案状态可恢复；不同账号不能读取对方会话；重新创建容器不丢状态；尚不开放真实业务写入。
- P2：接口与权限链路通过，能运行未训练/当前 checkpoint 的诊断评测；模型离线不导致任务失踪；质量缺口进 T2/T3。
- P3：未确认不落业务账；同一请求无重复效果；并发改账使旧预览失效；响应丢失仍可找到原结果。
- P4：真实手机网络下完成查询与确认写入；开关、换账号、断网和重启表现符合设计；主要原 App 功能不被阻断。
- P5：矩阵没有悄悄删掉的必做项，也没有仅返回解释却声称支持执行的写能力。
- P6：无未关闭的越权、重复记账、错误账务或数据恢复阻断问题。

**T 线通过条件（摘要自指南）**

- T0：训练资产清单、版本/适用性标注、可复现配置、失败样本处置表、最小部署链路验证记录。
- T1：新版覆盖矩阵、Schema/适配策略、数据适用性过滤、人工复核样本、独立 train/validation/sealed test 与预先记录的门槛。
- T2：可重现训练记录、候选 adapter/checkpoint、与原基线对比；loss 下降不单独构成通过。
- T3：实际模型 ID/格式/量化/上下文记录、工具调用及核心端到端报告。
- T4：覆盖 CAP01–CAP17 的模型报告、版本清单及发布候选；封存集调参即降级为回归。
